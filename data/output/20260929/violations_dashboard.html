Executive Summary

▼

This analysis identifies constraint violations for two Wikidata properties used in the WordNet ↔ Wikidata mapping ecosystem:

  • P8814 (WordNet synset ID): 1,977 violations found
  • P5063 (Interlingual Index ID): 784 violations found
Good News: 1,593 violations (57.7%) are valid mappings - legitimate cases of polysemy or semantic nuance that don't need fixing.
Action Required: 1,003 violations (36.3%) are real errors that need fixes on Wikidata.

🔍 Root Cause

The violations are caused by duplicate statements on Wikidata items, likely introduced when:

  • Multiple WordNet sources (OEWN + OENN) mapped the same synset/ILI to different QIDs
  • Wikidata imports from different versions or sources created duplicates
  • Manual additions of statements without checking for existing ones
✅ Confirmed: The source repositories (english-wordnet, english-namenet) are correctly mapped. The issue is Wikidata data integrity, not source repo quality.

🧠 Categorization Logic

  1. Check Synset Members: If Wikidata label matches synset members → likely valid
  2. Check Similarity: If semantic similarity > threshold → likely valid
  3. Check Polysemy: If both QIDs have valid but different meanings → legitimate polysemy
  4. Everything Else: Flag as potential error requiring fix

🎯 Fix Decision Process

  1. For P8814: Keep P8814 on the QID whose label appears in the synset members
  2. For P5063: Keep P5063 on the QID whose label/description best matches the synset definition
  3. For Ambiguous Cases: Use similarity scores to determine the best match

📄 PROPOSALS.md - Complete Content

📋 Executive Summary

This document outlines proposed fixes for P5063 (Interlingual Index ID) and P8814 (WordNet synset ID) constraint violations identified in Wikidata. Our analysis of 1,977 P8814 violations and 784 P5063 violations (as of 2026-11-01) reveals:

  • 856 real P8814 violations require fixes
  • 147 unique P5063 violations require fixes (312 total, deduplicated)
  • 1,003 total violations to be addressed on Wikidata
  • Source repos (english-wordnet, english-namenet) are NOT the primary issue

🎯 Key Finding

All fixes are on the WIKIDATA SIDE. The violations are caused by duplicate P5063/P8814 statements on Wikidata items, likely introduced when:

  • Multiple WordNet sources (OEWN + OENN) mapped the same synset/ILI to different QIDs
  • Wikidata imports from different versions or sources created duplicates
  • Manual additions of statements without checking for existing ones

The source repositories (english-wordnet, english-namenet) correctly define their mappings. The issue is data integrity on Wikidata.
