# WordNet to Wikidata Mappings

A pipeline for validating and importing synset-to-Wikidata mappings from Open English WordNet (OEWN) and Open English Namenet (OENN).

**[Open the interactive dashboard](https://yapy28.github.io/Wordnet2Wikidata-Mappings/)** — the full mappings table (26,695 pairs), the P8814/P5063 constraint-violation analysis, review queue, and proposed fixes in one self-contained page. Served via GitHub Pages; the same file, `index.html` at the repo root, also works offline. The link never changes: each run overwrites it.

## Overview

This project provides a complete pipeline for:

1. **Extracting** synset entries with Wikidata mappings from OEWN and OENN YAML sources
2. **Comparing** these mappings against current Wikidata links to identify missing connections
3. **Validating** mappings using deterministic match signals (synset ID, ILI, label, definition)
4. **Generating** QuickStatements batch files for importing missing links into Wikidata
5. **Verifying** successful import by regenerate comparison tables
6. **Analyzing constraint violations** for P5063 (ILI) and P8814 (synset ID) to identify and resolve duplicate mappings

## Workflow

### Core Import Pipeline

```
1. Extract:  extract_yaml.py → merged_mapped.csv
2. Fetch:    fetch_wikidata.py → wikidata_wordnet_links.csv  
3. Compare:  build_comparison_table.py → comparison_table.csv
4. Identify: Backlog CSVs (entries missing from Wikidata)
5-8. Clean, transform, validate and import via QuickStatements (done in Aug 2026; those scripts and
     docs/backlog_import.md are in archive/)
9. Verify:   verify_import.py (confirm successful import)
```

### Constraint Violation Analysis

```
1. Fetch violations:    fetch_violations.py → p5063_violations_from_wd.csv, p8814_violations_from_wd.csv
2. Classify:             categorize_all_final.py → p*_violations_final.csv (real error vs valid duplicate)
3. Source cross-check:   crosscheck_sources.py → source_crosscheck.csv (what english-wordnet / english-namenet say)
4. Proposals:            generate_proposals_v2.py → keep_decisions.csv, quickstatements/ (human decisions > source repos > heuristics)
5. Dashboard:            generate_dashboard.py → index.html (repo root)
6. Review sheet:         export_review_sheet.py → review_sheet.xlsx → collaborators fill it in Google Sheets
7. Decisions back:       import_decisions.py <downloaded.xlsx> → manual_review/decisions.csv, then re-run from step 4
8. Apply fixes:          Submit removals to Wikidata via QuickStatements (after review + a test batch)

Steps 2-6 (plus the tests) run with one command: python scripts/run_pipeline.py
```

## Properties Used

- **P8814**: WordNet synset ID - Links Wikidata entity to WordNet synset
- **P5063**: Interlingual Index (ILI) - Links Wikidata entity to cross-lingual concept

## Constraint Violation Analysis

The system includes comprehensive analysis of Wikidata constraint violations for P5063 and P8814 properties:

### Key Features

- **Automated Fetching**: SPARQL queries fetch live violation data from Wikidata
- **Categorization**: Automatic classification of violations as real errors or valid duplicates
- **Similarity Matching**: Uses semantic similarity (label, definition, synset members) to score mappings
- **Proposal Generation**: Generates QuickStatements to fix real violations
- **Comprehensive Tracking**: Full comparison table tracks all violations and their proposed fixes

### Statistics (as of current data)

- **P8814 Violations**: 1,977 total, 856 real violations identified
- **P5063 Violations**: 377 unique (QID, ILI) pairs (784 raw SPARQL rows), 147 real violations identified
- **QuickStatements Generated**: 440 P8814 fixes + 75 P5063 fixes = 515 total
- **Reconciliation**: 2,354 statements = 1,351 valid + 488 keep + 515 remove

python scripts/verify_import.py \
  --old data/output/comparison_table.csv.backup \

## Adding new mappings (after the clean-up)

Only nouns carry QIDs in the source repos (13,301 OEWN nouns linked vs 58,571 unlinked; OENN: 12,700 vs 345);
most unlinked nouns are ordinary concepts without a Wikidata item, so the hard part is **precision**, not coverage.

1. **Candidates**: unlinked noun synsets, entity-like first (species, places, people, organisations, products).
2. **Match**: search Wikidata by lemma; score with the same evidence as this analysis (label in members, definition vs description, instance-of/hypernym agreement).
3. **Validate** with the shared check "would this statement create a duplicate or conflict?" (the logic behind `crosscheck_sources.py`), so we never add what we are cleaning up.
4. **Human review** of every proposed pair; auto-accept only exact label + hypernym agreement.
5. **Write both sides**: QuickStatements to Wikidata, PRs to the source repos.
6. **Verify** with a re-fetch of the violation reports.
